# DSH Mobile v1.4.24

> 本版三件事：插件中心接入社区目录（3540 个插件）、设置页重新分区、引擎异常退出
> 后彻底清场再重启。上一版引入的社区手机版 UI 插件已移除。

## 插件中心：接入 dsh-market 目录

从「npm 搜索」换成社区维护的插件目录（[dsh-market](https://github.com/dsh-market/dsh-market)）：

- **3540 个插件**（此前只有几十到上百条搜索结果）；
- **23 个分类**，顶部横滑筛选——UI 增强、工具与能力、会话与消息、记忆、主题外观……
- **中英双语描述**，跟随界面语言自动显示；
- **离线可用**：目录内置在安装包里，打开即显示，不再等网络；搜索在本地完成，零延迟。

## 手机版 UI：回到自有实现

上一版内置的社区手机版 WebUI 插件在实际使用中 bug 较多（快捷栏消失、面板错乱、
会话删除异常），本版已整体移除。手机窄屏适配回到项目自有的四个插件，行为与
v1.4.21 一致。

## 设置页重新分区

原来 4 个大分区、22 项平铺，现在拆成 **8 个语义分区**：

`外观与交互` · `权限与能力` · `语音` · `扩展` · `数据与会话` · `网络` · `诊断与维护` · `关于`

同时把图标全部去重——此前 4 个图标被重复使用（只换了颜色），现在 25 个设置项
**每项图标都不同**，能靠形状直接辨认。「Root 能力」「Shizuku 状态」也从权限行里
独立出来成为单独条目。

## 引擎异常退出：彻底清场后完整重启

用户反馈「进程异常退出后反复重启、起不来」。原因是旧逻辑只在探测到端口被占时
才清场，且只杀命令行匹配引擎 node 的进程——而进程退出不等于端口释放，包装层
（su 外壳、僵尸孙进程）还会让命令行匹配失效。

现在的做法：异常退出后，**按端口找到持有 4080 的进程全部清掉**（不论它是什么），
确认端口真正释放，再完整启动一遍引擎，效果等同于关掉应用重开。局域网反向代理
不受影响（它监听别的端口）。

## 登录失效不再无限重启

若引擎因登录态 / API Key 过期而起不来，以前会重试到上限（表现为长时间反复重启）。
现在识别这类失败后直接停下，并提示「登录状态或 API Key 已失效，请重新登录」——
重启解决不了的问题，就不再重启。
